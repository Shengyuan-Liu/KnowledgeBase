# Preserve selected PDF table evidence and quoted document scope

The frozen dense-table failure is repaired at the context and scope boundaries.
On the four original requests with recorded retrieval candidates, final structural
evidence coverage improves from **2/16 to 16/16 requested point instances** under
the unchanged 4,096-token budget. The two questions previously rejected by scope
now resolve locally to the ready PDF. They have no original candidate rankings,
so their offline replay does not establish new retrieval or answer success.

## Implementation

Table coordinate JSON uses compact separators without dropping coordinates,
zero-width blank positions, merged header bounds, table identity, or canonical
text. The target child shrinks from **4,673 to 3,346 tokens**; its source body
remains 501 tokens. The format identifier is `source-metadata-pdf-v2`.

Compaction alone was insufficient: the first notes hit could now expand to a
3,382-token parent containing unrelated table rows, excluding the target child.
The final default packing path therefore defers PDF table parent expansion until
selected children have been tried. Each deferred parent replaces only its own
siblings, in selected-rank order, and must fit without removing any unrelated
retained source. Parents without PDF tables and the `parent_first` control retain
their prior behavior. This is a PDF-specific repair, not a global child-first
policy; an earlier TXT/GPA parent-context regression remains part of the history.

Exclusion diagnostics keep `token_count` as source-body tokens and add optional
`trial_context_tokens` for the entire failed numbered context, including other
sources. The debug view displays that total against the budget. Historical
snapshots without the new field remain readable.

Quoted document references stop at the closing quote, so the date following
`"background-checks.pdf"` stays in the question. Selected-file restrictions and
ambiguity handling remain. Planned mode preserves the original unresolved scope
and its clarification rather than resolving again against an empty catalog.
JSON, SSE and saved history retain the same clarification, without provider calls.
